What the AI wrote, and what I rewrote or rejected: The AI wrote all the code. I guided it through the CLAUDE.md, TEST_QUALITY.md and example code from prior, long standing projects of mine. I use plan/act cycles to ensure that the AI understands what it is that I want it to write so there was no need for rewrites. My rejections come very early in the process where the AI has the tendency to over-engineer solutions so most of my rejections were in the PRD and TDD to ensure that the scope was appropriate for the time available and the fact that the project is a demonstration and not intended to be a production system. The AI was unaware of Jev so I had to pull in some education on that new model.
What broke and how I debugged it:
(1) Claude found a regex bug it created once I introduced testing.
(2) The PRD was loose in terms of specifying routing (single vs multi-destination). I noticed the issue, had Claude find all the touchpoints and added documentation clarification and TODOs in the code.
(3) In the PRD section 5, Claude missed the much bigger opportunity in every enterprise.
(4) Claude missed some very typical, real world requirements of enterprise tenants in the PRD/TDD so I described the requirements and had Claude update the docs.
(5) Claude unnecessarily extended the scope to include a replayable audit log - it was not one of our depth areas (we have two others) so not necessary in this v1. I instructed Claude to reduce scope.
(6) When prompted, Claude found many situations where the implementation didn't match the TDD commitment and was able to resolve each of them.
(7) Claude wrote prompts that relied on the LLM giving offsets into strings to find citations etc. This is extremely error prone and the opposite should be done - return the substring and have deterministic code find the index.
(8) --confirm_llm output was not human-readable - simple fix for Claude once spotted.
(9) Claude Code regularly mixes up the Rubrics and Details section of prompts on a new project. I need to clarify my prompt conventions file.
(10) Claude mistakenly used the system state Pydantic models into the Structured Output models. It's an obvious bug when you inspect the prompts using --confirm_llm. The fix is to have a Structured Output model per call that is then wrapped or augmented by the full state model.
(11) Running the pipeline highlighted a mismatch between prompt and code indexing into passages.
(12) Claude doesn't understand that worked examples in prompts should not be taken from the examples we're testing with.
(13) Claude tends to unnecessarily 'narrate' prompt modifications in the prompt. --confirm_llm allows us to inspect and issue corrections.
(14) Claude put JSON examples after the Inputs section of the prompt which misses an opportunity for input token caching.
(15) gpt-5.4-nano was clobbering white space which made citation verification less than optimal - we fixed it through whitespace normalization.
(16) Claude implemented a 1:1 mapping between changes and all company assets, which is not realistic. I spotted this in the UI and redirectd Claude to refactor as a mapping between changes and each asset individually.
(17) Claude included max_tokens in the ModelCaller cache key - which is wrong - I spotted it in a review of TDD.md and directed the change.
(18) Many other tweaks and corrections across > 120 commits.
