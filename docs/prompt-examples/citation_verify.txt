## Task

## Steps
1. For each change block in the Inputs section, read the description.
2. For each non-null citation side, read the citing span AND the full passage text that contains it.
3. Decide verification per side:
   - tightened/loosened prior_citation: span should show the pre-change state of the modified obligation (the parent obligation BEFORE the parameter change).
   - tightened/loosened new_citation: span should show the new state INCLUDING the specific parameter named in the description.
   - added new_citation: span should show the new standalone action.
   - removed prior_citation: span should show the obligation that was removed.
4. Verified=true requires the span to substantively support the specific claim in description — not merely sit in the right paragraph.
5. For null citations (added has null prior; removed has null new): verified=null and rationale=null.
6. For sides rendered as "GROUNDING_FAILED (do not verify this side — handled upstream)": emit verified=null and rationale=null — the grounding failure is already recorded upstream.

## Details
Example 1 — strong support (verified=true):

  new_citation.citing span: "and shall document a written policy identifying the individuals authorized to make minimum-necessary determinations"

Example 2 — right paragraph, wrong content (verified=false):
  Description: "The capability-confirmation obligation is tightened by adding a required telemetry feed for aggregated resources rated at or above 100 kW."
  new_citation.citing span: "the resources in the aggregation have the capability to provide the services for which the aggregation is bidding"
  Correct: new_citation_verified=false. The span is from the same paragraph as the new telemetry requirement, but says NOTHING about telemetry or the 100 kW threshold — it is the pre-change capability language, not the post-change tightened state. new_citation_rationale: "cited span addresses capability confirmation but does not mention telemetry feed or the 100 kW threshold named in the description".

Example 3 — parent-obligation span is correct for a tightened change's prior_citation (verified=true):
  Description: "The SAR-filing obligation is tightened by adding a 30-day deadline and a required wire-routing-path data element."
  prior_citation.citing span: "shall file a suspicious activity report with FinCEN when a transaction over $5,000 meets any of the identified reporting criteria"
  Correct: prior_citation_verified=true. The span is the pre-change parent obligation (file a SAR with FinCEN) whose parameters the new version tightens. prior_citation_rationale: "span is the pre-change SAR-filing duty whose timing and data-element parameters the new version tightens".

## Rubrics
- prior_citation_verified=True only when the prior passage text substantively supports the described change (as the pre-change state).
- new_citation_verified=True only when the new passage text substantively supports the described change (as the post-change state).
- When a change has no prior_citation (e.g. change_type="added"), set prior_citation_verified and prior_citation_rationale to null.
- Same for new_citation when change_type="removed".
- Rationale should quote the specific supporting phrase from the passage — do NOT restate the description.

## Pitfalls
- Do NOT verify=true when the span is in the right paragraph but does not mention the specific parameter / action named in the description. "The passage is topically relevant" is NOT the same as "the span substantively supports the specific claim" — see Example 2.
- Do NOT paraphrase the description in the rationale. The rationale MUST quote the specific supporting phrase from the passage/span; it is the auditor's receipt that the span actually says what the description claims.
- Do NOT verify=false merely because the prior_citation span lacks the new parameter named in the description. A tightened/loosened prior_citation shows the pre-change parent obligation; it is CORRECT for it not to contain the tightening parameter — that lives in the new_citation. See Example 3.
- When a citation side is rendered as "GROUNDING_FAILED (do not verify this side — handled upstream)", the structural grounding step upstream could not locate the citing span in the passage. That side is already recorded as unverified; emit verified=null and rationale=null for it. Do NOT attempt to verify from the description alone.

## Field Intents
- change_index: 0-based index into the input change list (the "[N]" prefix on each rendered change block). Must be a valid index into that list.
- prior_citation_verified: true/false if the Change has a prior_citation; null if the Change has no prior_citation (e.g. change_type="added").
- prior_citation_rationale: short quoted supporting phrase from the passage if verified=true; a one-sentence refutation naming what the span does NOT support if verified=false; null when prior_citation_verified is null.
- new_citation_verified / new_citation_rationale: same pattern for the new_citation.
